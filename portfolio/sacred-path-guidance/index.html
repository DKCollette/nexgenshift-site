WORKING PROTOTYPE
Sacred Path Guidance

A 12-page tarot and spiritual-guidance booking site: services, live availability, double-booking-safe reservations, and a token-gated owner dashboard. Screenshots below are the real running site with sample data.

Objective

Give a spiritual practitioner one home base: explain the offerings, let seekers check availability and request readings, and manage everything from a private dashboard — no patchwork of tools.

Problem

Bookings arrived by DM, availability lived in someone's head, and double-bookings happened. There was no single place to show services, take requests, and track clients.

Solution

A full marketing site plus booking engine: 12 public pages (home, readings, guidance, about, testimonials, pricing, privacy, terms), services + availability APIs, server-side double-booking prevention, spam-protected contact, and an owner dashboard for bookings, messages, testimonials, FAQs, and settings.

Technology

Dependency-free Node API serving static pages. Token-gated owner dashboard; honeypot + rate limiting on contact; moon-phase display clearly labeled as an approximation. 38/38 smoke checks green.

Verified features

What it does today.

  • 12-page marketing site with readings, pricing, testimonials
  • Live availability + bookings with double-booking prevention
  • Contact form with honeypot + rate limiting
  • Owner dashboard: services, prices, availability, bookings, messages, FAQs, settings
  • Booking confirm/cancel flows

Status & honest limits

Working prototype — the strongest of the three builds. Honest limits: no payments are collected (paymentStatus: not_collected); no email sending — bookings and messages persist for the owner to follow up. Testimonials ship as 3 clearly-labeled SAMPLE placeholders the owner replaces. Screenshots show public pages only; the admin dashboard is never published.
